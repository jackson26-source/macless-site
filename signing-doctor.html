Signing Doctor: find out why your iOS or Android build won't sign

Point it at a .mobileprovision (and optionally a .p12), or an Android release .keystore — it decodes them and tells you exactly what's wrong, instead of the generic error xcodebuild or Google Play give you.

Works with any Xcode or Android project, any CI system — not just Macless's own pipeline.
$ ./signing-doctor.sh --profile App.mobileprovision --cert dist.p12
Team ID:            ABCDE12345
Bundle ID:          com.example.app
FAIL  Your certificate's fingerprint does NOT match any certificate
      embedded in this profile. This usually means you regenerated one
      (the cert after the old one expired, or vice versa) without
      regenerating the other to match.

What it catches

These are the failures that produce the least helpful native error messages — the ones that send people down a Stack Overflow rabbit hole instead of telling them what's actually wrong.

  • A corrupted or mis-encoded profile fileThe single most common first-time mistake — Xcode's own error for this tells you nothing useful.
  • An expired (or soon-to-expire) provisioning profileCaught with an exact day count, before it silently breaks your next build.
  • A Team ID or bundle ID mismatchCompares the profile against what you expect, wildcard App ID profiles handled correctly.
  • A certificate that doesn't match its profileThe hardest of these to self-diagnose — a profile only trusts the specific certificate(s) it was generated against, and regenerating one without the other is a very common, nearly invisible "why won't this codesign" cause.
  • An Android keystore that won't openWrong password or mismatched alias — the Android equivalent of the corrupted-profile problem, and keytool's own error is just as unhelpful.
  • An expired Android signing keyGoogle Play rejects any update signed with an expired key, and unlike iOS you generally can't just regenerate a fresh keystore for an app already published.
This is the same "validate signing setup" step pulled straight out of Macless's own ios-testflight.yml / android-build.yml workflows, generalized so it's useful whether or not you ever buy the full template.

Two ways to run it

As a shell script, anywhere

# iOS
$ ./signing-doctor.sh --profile App.mobileprovision \
    --expected-team-id ABCDE12345 \
    --expected-bundle-id com.example.app \
    --cert dist.p12 --cert-password "..."

# Android
$ ./signing-doctor.sh --android-keystore release.keystore \
    --android-keystore-password "..." --android-key-alias upload

As a GitHub Actions step

- uses: jackson26-source/macless-signing-doctor@v1
  with:
    profile-path: ${{ runner.temp }}/app.mobileprovision
    expected-team-id: ABCDE12345

iOS checks need macOS (it shells out to security, PlistBuddy, and openssl) — run it locally on a Mac or as a step on a macOS GitHub Actions runner. Android checks only need keytool and openssl, so those run anywhere, including a plain Ubuntu runner.
