Fix "Missing Compliance" in TestFlight

The build is there. Nobody can install it. One Info.plist key ends this permanently — but read what you’re declaring before you set it.

Jackson · August 2026

Your build uploads, processing finishes, and then it just sits there. In App Store Connect the build shows Missing Compliance, and your testers see nothing at all — the build exists but isn’t installable until you answer a question.

That question is export compliance. US export regulations require Apple to know whether your app uses encryption, and Apple asks per build. Answer it in the web UI and that one build unblocks. Answer it in your Info.plist and it never asks again.

Why this hits CI builds harder

Locally you notice immediately — you’re already in App Store Connect looking at the build. In an automated pipeline nobody is watching, so the release completes, the workflow goes green, and the build sits in limbo until someone happens to check. The pipeline reports success because from its side the upload genuinely succeeded.

The key

Add this to your app’s Info.plist:

<key>ITSAppUsesNonExemptEncryption</key>
<false/>

With that present, App Store Connect stops asking and builds go straight to testable.

Read this before you set it to false. That key is a declaration you are making, not a checkbox to silence a warning. false says your app uses no non-exempt encryption. Apps that only use standard HTTPS/TLS through Apple’s own networking APIs are normally in exempt territory — which covers most apps — but if you ship proprietary or non-standard cryptography, the answer is different and there may be documentation you’re required to file. If you’re not certain what your dependencies do, that’s worth an hour of checking rather than a guess. Apple’s export compliance documentation is the authority here, not this page.

Where the key actually has to live

It has to be in the Info.plist that ends up inside the built app bundle, not a copy sitting somewhere in your project. Cross-platform frameworks are where this goes wrong: in Capacitor the file is at ios/App/App/Info.plist, in React Native at ios/<YourApp>/Info.plist, and in Flutter at ios/Runner/Info.plist. Editing the wrong one produces exactly the same symptom as not editing anything.

Confirming it worked

Upload one build. If it goes straight to testable without a compliance prompt, the key is in the right place. If it still says Missing Compliance, the key isn’t in the bundle that was uploaded — check the built .app rather than the source file.
