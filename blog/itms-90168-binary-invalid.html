Fix ITMS-90168: "The binary you uploaded was invalid"

This is Apple's catch-all — the message is identical whether the real cause is your architecture, your Info.plist, or your embedded provisioning profile. Here's how to actually find out which.

Jackson · August 2026

Unlike ITMS-90683 or ITMS-90717, which each mean one specific thing, ITMS-90168 is genuinely a catch-all — Apple's validator uses it for several unrelated failures, and worse, it often shows up with no further detail at all. If you've gotten this with an empty or unhelpful message body, don't start guessing; run local validation first, which almost always surfaces the real reason.

Get the real reason with local validation before resubmitting blind

Apple's own validator will usually tell you what App Store Connect's rejection email didn't:

xcrun altool --validate-app -f YourApp.ipa -t ios \
  --apiKey YOUR_KEY_ID --apiIssuer YOUR_ISSUER_ID

or with the newer notarization tool:

xcrun notarytool submit YourApp.ipa --apple-id you@example.com \
  --team-id XXXXXXXXXX --password app-specific-password --wait

This step alone resolves most cases of "the error message told me nothing," because local validation returns the specific underlying complaint instead of the generic ITMS-90168 wrapper App Store Connect sometimes shows.

The most common actual causes, roughly in order of likelihood

Missing or wrong architecture slice. If your build was archived on Apple Silicon but a dependency was compiled for the wrong slice (or vice versa), the binary can look valid locally and still fail server-side validation. Check lipo -info on the actual executable inside the .app bundle to confirm which architectures it contains.

Invalid or missing Info.plist keys. A malformed CFBundleVersion or CFBundleShortVersionString (non-numeric, or not incremented from the last build), or a missing required key, fails validation without always being called out by name.

Embedded provisioning profile problems. A profile embedded in the archive that's expired, or doesn't match the entitlements actually compiled into the binary, can surface as this generic error rather than a signing-specific one — worth checking the entitlements-mismatch cause covered in this post even if the message doesn't mention entitlements directly.

Symlinks or extended attributes inside the archive. Less common, but a .ipa zipped with the wrong tool (rather than through Xcode's own export step) can carry symlinks or macOS extended attributes that Apple's validator rejects outright. If you're building the .ipa manually in a CI script rather than letting xcodebuild -exportArchive produce it, this is worth ruling out specifically.

If local validation itself fails to even run, that's actually useful information on its own — it usually means the archive itself is malformed (a bad export options plist, or an interrupted archive step) rather than anything about App Store Connect's review, which narrows the search considerably.
