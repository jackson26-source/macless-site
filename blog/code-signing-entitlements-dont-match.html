Fix "Provisioning profile doesn't match the entitlements file"

The error names two entitlement keys, but it's almost always one of two root causes — and neither of them is "your entitlements file is wrong."

Jackson · August 2026

The full error usually reads something like: Provisioning profile "YourApp App Store" doesn't match the entitlements file's values for the application-identifier and keychain-access-groups entitlements. It sounds like your .entitlements file has the wrong values, but in practice the entitlements file is almost always fine — what's actually out of sync is what the provisioning profile on Apple's portal has been generated to allow.

1. A capability was added in Xcode but never enabled on the profile

This is the most common cause. Turning on a capability in Xcode's "Signing & Capabilities" tab — Push Notifications, App Groups, Associated Domains, Keychain Sharing — immediately updates your local .entitlements file and your App ID's configuration if Xcode has portal access. It does not retroactively update a provisioning profile you already generated and downloaded earlier. That profile still only grants the capabilities it had at the moment it was created.

Fix: in the Apple Developer portal, open the App ID, confirm the new capability is actually checked there, then regenerate the provisioning profile itself (not just re-download the old one — an unchanged profile keeps its old capability set even if you download it again) and update the base64 secret your CI workflow uses.

2. keychain-access-groups still points at the wrong team or app ID prefix

keychain-access-groups in the entitlements file is typically written as $(AppIdentifierPrefix)com.yourcompany.yourapp. If the entitlements file was copied from a different target, a different app, or an older version of the project, that literal string sometimes gets hardcoded to the wrong prefix instead of using the $(AppIdentifierPrefix) build variable. Since that variable resolves to your team ID at build time, a hardcoded mismatch here fails signing even though every other value looks correct at a glance.

Check it directly rather than trusting Xcode's UI — open the raw entitlements file and confirm every keychain-access-groups entry actually uses the $(AppIdentifierPrefix) variable, not a typed-out team ID.

Fast way to check which one you've hit: run security cms -D -i /path/to/profile.mobileprovision and look at the Entitlements dictionary it prints — compare it key-by-key against your project's .entitlements file. Whatever capability or value is present in one and missing in the other is the actual mismatch, rather than guessing from the error text alone.

Why wildcard App IDs make this worse

A wildcard App ID (com.yourcompany.*) can't carry most capabilities at all — Push Notifications, App Groups, and several others require an explicit App ID. If your project is signed against a wildcard profile and you add one of these capabilities in Xcode, this exact error is what shows up, because there's no version of that profile that could ever satisfy it. The fix there isn't regenerating the profile — it's switching to an explicit App ID and generating a new profile against it.
