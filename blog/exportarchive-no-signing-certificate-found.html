Fix "exportArchive: No signing certificate found" in CI

This is a different failure than "no signing certificate matching team ID" — the archive step already worked, which rules out most of the usual causes.

Jackson · August 2026

This one is confusing specifically because of where it happens. Your xcodebuild archive step succeeds — Xcode built and signed the app fine. Then the separate xcodebuild -exportArchive step, which turns that archive into an actual .ipa, fails with something like:

error: exportArchive: No signing certificate "iOS Distribution" found

If the certificate weren't in the keychain at all, the archive step would have failed first. So the certificate is there — exportArchive is failing for a narrower reason.

The usual cause: archive and export used different signing methods

Archiving can succeed using automatic signing (Xcode or your build settings pick a certificate and profile on the fly), while your exportOptions.plist tells the export step to use manual signing with a specific certificate identity or profile — and that exact identity isn't what actually got used to sign the archive. Export re-validates against what you explicitly asked for, not against whatever worked during archiving.

Check your exportOptions.plist for a mismatch between:

  • signingStyleShould be manual in CI — automatic in a non-interactive environment is a common source of this exact error, since there's no UI for Xcode to resolve ambiguity through.
  • provisioningProfiles dictionaryEach bundle ID key must map to a profile that's actually installed in the CI runner and actually signed with the certificate present in the keychain — not just a profile that exists in Apple's portal.

The other cause: the certificate has a private key issue

A .p12 can import into the keychain "successfully" and still not be usable for signing if the private key didn't come through with it — this happens when the certificate was exported from a machine that generated the key differently, or the export step dropped the key pairing. Archiving can sometimes get away with this depending on which signing path Xcode takes internally; exporting cannot. Confirm the identity has an actual private key attached:

$ security find-identity -v -p codesigning

If the certificate shows up here with a valid count, the key is attached. If it's missing or shows "0 valid identities found" despite the import step reporting success, re-export the .p12 from the original source (Keychain Access, or wherever the certificate was generated) rather than reusing the existing file — a key pairing issue isn't something you can fix after the fact.

Quickest way to isolate which of these it is: temporarily set signingStyle to automatic in a throwaway copy of exportOptions.plist and rerun just the export step. If that succeeds, the problem is a mismatch in your manual signing config, not the certificate itself.
