Can Bolt.new publish your app to the App Store and Google Play?

Yes, if the project is a mobile app. Bolt builds iPhone and Android apps on Expo, and its docs walk you through publishing to TestFlight, the App Store and Google Play. You run the build and submit commands yourself from a terminal.

Jackson · October 2026, updated November 2026

Which Bolt projects can go to the stores?

The ones started as mobile apps. Bolt's Expo page says to mention a mobile app in your very first prompt, because projects created for web don't easily switch over to mobile. If your Bolt project began as a web app, the Expo route isn't the one open to you, and getting it onto a phone becomes a wrapping job.

What does Bolt's own guide have you do?

The prerequisites in the docs are a computer with Node.js and Git, an Expo account, an Apple Developer account for iPhone apps and a Google Play Developer account for Android. The guide doesn't ask for a Mac. Expo's EAS service does the building.

You download the code from Bolt, install the EAS command line tool, log in, install dependencies and run a setup check. You set the app's name and slug in app.json, and the guide warns that you can't change the slug after your first build. Then you run the EAS init and build configure commands.

For iPhone, one command builds the app, creates the listing in your Apple Developer account, sets up a TestFlight testing group and submits the build for internal testing. For public release you go to App Store Connect, fill in the app's details and submit for review.

For Android, you run a production build, download the file, create the app in Google Play Console, set up internal testing, then create a production release and submit it for review.

What does the guide leave to you?

Everything after the build command. The store listing, the screenshots, the privacy policy and the answers to App Review are all yours. The guide's troubleshooting section is three short entries: a failed build means checking your certificates, a crash means reading the error logs in the Expo dashboard, and a rejected upload means making sure the app meets Apple's and Google's requirements. That's the full extent of the rejection advice.

Updates work the same way. A web update is one export and deploy. A mobile update means downloading the code from Bolt again, rebuilding and resubmitting.

Can a Bolt app take subscriptions on iPhone?

Bolt's docs point to RevenueCat for in-app purchases and link a guide for adding it to a Bolt-generated Expo app. The page says it can be used in iPhone apps as well as Android. That's a real difference from builders that wrap a web app, where Apple's payment system isn't reachable.

Summary

Bolt documents a complete path to both stores for mobile projects, and it's more than most builders offer. The path ends at your terminal and your App Store Connect account, and everything that happens in review is yours.
