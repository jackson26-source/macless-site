Fix ITMS-90683: "Missing purpose string in Info.plist"

Unlike most ITMS errors, this one only means one thing. The hard part is finding which key, not what the error means.

Jackson · August 2026

ITMS-90683 is one of the more useful App Store Connect errors, because it's specific: your app links against a framework that can access a privacy-sensitive API — camera, location, contacts, microphone, photo library, and so on — and your Info.plist is missing the matching NS...UsageDescription key explaining to the user why. Apple requires that string to exist before it'll accept the binary at all, whether or not your app actually calls that API at runtime.

Find which key is actually missing

The rejection email usually names it directly, in a line like:

ITMS-90683: Missing purpose string in Info.plist - Your app's code
references one or more APIs that access sensitive user data. The
app's Info.plist file should contain a NSLocationWhenInUseUsageDescription
key with a user-facing purpose string explaining clearly and completely
why your app needs the data.

If the email is vague or you're checking before you submit, the fastest way to find every key your binary actually needs is to search the compiled binary itself for known API symbols, or more simply, grep your own project and every linked SDK's source for the usage-description-triggering APIs (location, camera, microphone, contacts, calendar, photos, bluetooth, tracking). The common keys, if you need to check your Info.plist against the full list: NSCameraUsageDescription, NSMicrophoneUsageDescription, NSLocationWhenInUseUsageDescription, NSPhotoLibraryUsageDescription, NSContactsUsageDescription, NSCalendarsUsageDescription, NSBluetoothAlwaysUsageDescription, NSUserTrackingUsageDescription.

Why this often isn't a key you added yourself

The most confusing version of this error happens when your app doesn't call the sensitive API directly at all — a dependency does. Analytics SDKs, ad networks, and cross-platform framework plugins (Capacitor and Cordova plugins especially) frequently link against location or tracking frameworks internally, even for features you're not using. Apple's static analysis flags the linked capability, not just your own code, so the fix is still adding the key to your own Info.plist — you just have to go find which plugin pulled it in, usually by checking that plugin's own install notes or `Info.plist` requirements in its documentation.

Write a real purpose string, not a placeholder

Apple also rejects usage strings that are empty, generic, or clearly a placeholder ("This app needs your location" gets flagged more often than you'd expect). The string has to actually explain what the app does with the data, in user-facing language — write it like something a real person would read in the system permission prompt, because that's exactly where it appears.

If you're using a cross-platform framework (Capacitor, Cordova, React Native, Flutter), add the key to the native Info.plist in your iOS project folder directly — not to a JS/Dart-side config file that may or may not get synced into it. A stale native project that hasn't picked up a config change is one of the more common reasons this error reappears after you thought you'd fixed it.
