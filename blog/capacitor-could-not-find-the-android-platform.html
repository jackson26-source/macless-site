Capacitor: "Could not find the android platform"

Hit while wiring the Android pipeline. The message points at the platform; the cause is a package that was never installed — and the obvious fix breaks in a second way.

Jackson · August 2026

You run the command that every guide tells you to run, and it refuses:

npx cap add android
[error] Could not find the android platform

Nothing is corrupt. Capacitor 5 and later ship each platform as a separate npm package, and @capacitor/android simply isn’t installed. Older Capacitor bundled the platforms into the CLI, which is why so much of the advice you’ll find doesn’t mention installing anything.

This bites hardest if you set iOS up first — a very normal order for anyone shipping to the App Store before Google Play. You install @capacitor/ios, everything works, and months later Android fails on a message that sounds like a missing folder rather than a missing dependency.

The fix, and the trap inside it

The obvious move is npm install @capacitor/android. That installs the latest major, which fails a second way if your project is on an older core:

npm error ERESOLVE could not resolve
peer @capacitor/core@"^7.0.0" from @capacitor/android@7.x

The platform package’s major version has to match @capacitor/core. Check what you actually have, then install that major:

# what core version is this project on?
npm ls @capacitor/core

# install the matching major, e.g. core 6.x:
npm install @capacitor/android@^6.0.0
npx cap add android

Found the hard way. This is one of two bugs a live end-to-end test of the Macless Android pipeline caught on a throwaway repo — the other being a JDK version mismatch that surfaces a few steps later. Both are the kind of thing you only meet by running the whole thing start to finish rather than reading the docs.

After it succeeds

Run npx cap sync android to copy your web build in and update native dependencies. If you’re doing this in CI, both commands need to run on a runner with the Android SDK available, and npx cap add android should be treated as idempotent setup — it fails if the android/ directory already exists, so guard it or commit the platform directory and skip it entirely.

The pipeline handles this automatically

Macless’s Android workflow detects your installed Capacitor core version and installs the matching platform package before it builds — this was found and fixed during a real end-to-end test.
