Gradle: "invalid source release: 21"

The build gets a long way in before dying. Capacitor 7 wants Java 21; your runner gave it 17.

Jackson · August 2026

Gradle runs, resolves dependencies, compiles for a while, and then:

> Task :app:compileReleaseJavaWithJavac FAILED
error: invalid source release: 21

The message reads like a Gradle configuration problem. It isn’t. The JDK running the build is older than the Java version the project targets. Java 17 has no idea what source release 21 means, so it refuses before compiling anything.

Why this appears out of nowhere on Capacitor 7

Capacitor 7’s Android template compiles against Java 21. Most CI images still default to JDK 17 — a sensible default that was correct until it wasn’t. So a project that builds fine on a developer machine with a newer JDK installed dies on the runner, and nothing in the error mentions either version except the bare number 21.

It also explains why upgrading Capacitor can break a pipeline that hasn’t otherwise changed. Nothing in your workflow file changed; the template you regenerate from did.

The fix

Pin the JDK explicitly rather than relying on the runner default. In GitHub Actions:

- uses: actions/setup-java@v4
  with:
    distribution: temurin
    java-version: '21'

That step has to run before any Gradle step. Setting JAVA_HOME after Gradle has already started won’t help.

Check what you’re actually targeting

Before assuming 21, confirm what the project wants — look in android/app/build.gradle:

compileOptions {
    sourceCompatibility JavaVersion.VERSION_21
    targetCompatibility JavaVersion.VERSION_21
}

Match your CI JDK to that number. Installing a newer JDK than the target is generally fine; installing an older one is what produces this error.

Found the hard way. This surfaced during a live end-to-end test of the Macless Android pipeline, a few steps after the missing platform package. Two failures, one test run — which is a reasonable argument for running any pipeline start to finish on a throwaway repo before trusting it with a real release.

The workflow already pins the right JDK

Macless’s Android pipeline sets up JDK 21 rather than the runner default, because a real end-to-end test failed exactly here first.
